## 一、 算力集群网络拓扑与高速总线架构

千卡大模型预训练（Pre-training）对跨节点通信延迟与带宽极其敏感，集群采用**无阻塞两层 Fat-Tree（Spine-Leaf）全对称拓扑**：

### 1.1 节点硬件配置与网络架构
- **单计算节点规格**：
  - 计算单元：8 张 NVIDIA H800 SXM5 80GB HBM3 GPU。
  - 卡间互联：每节点通过 4 颗 NVLink Switch 芯片互联，双向卡间双向通信带宽达 **900 GB/s**。
  - 节点对外网卡：配置 8 张 400Gbps NVIDIA ConnectX-7 (CX7) PCIe 网卡，实现 **GPU 与网卡 1:1 独立绑定（NUMA 对齐）**。
- **集群网络协议**：
  - 采用 **RoCE v2（RDMA over Converged Ethernet）** 协议。
  - 交换机开启全局 **PFC（Priority Flow Control，优先级流控）** 与 **ECN（Explicit Congestion Notification，显式拥塞通知）**，实现端到端严格零丢包网络环境。

## 二、 NCCL 通信故障排查与超时环境变量规范

在大规模分布式数据并行与张量并行（3D 并行）训练中，多卡间的 All-Reduce、All-Gather 依赖 NCCL 库执行环形（Ring）或树形（Tree）通信。

### 2.1 生产级 NCCL 环境变量强制规范
集群所有提交的 Kubernetes / Slurm 训练 Job 必须注入以下环境变量基线：

```bash
# 开启 NCCL 详尽调试日志与通信子图输出
export NCCL_DEBUG=INFO
export NCCL_DEBUG_SUBSYS=INIT,COLL,ENV,NET

# 开启异步错误处理，防止单卡卡死导致整个集群永久无响应挂起
export NCCL_ASYNC_ERROR_HANDLING=1

# NCCL 通信看门狗心跳超时时间：严格设定为 1800 秒（30 分钟）
# 超出 1800 秒无心跳，NCCL 自动抛出 SIGABRT 并触发集群故障自愈调度
export NCCL_TIMEOUT=1800

# 优化 RoCE v2 网络自适应路由与多队列拥塞规避
export NCCL_IB_DISABLE=0
export NCCL_IB_HCA=mlx5_0,mlx5_1,mlx5_2,mlx5_3,mlx5_4,mlx5_5,mlx5_6,mlx5_7
export NCCL_IB_GID_INDEX=3
export NCCL_IB_TC=106
```

### 2.2 典型通信挂起（NCCL Hang）三步排查法
1. **排查慢节点（Straggler Node）**：
   - 查看 Prometheus 监控看板中的 `gpu_kernel_execution_time`，若某单卡执行矩阵乘法耗时超过同批节点均值 **15%**，判定为掉频慢卡。
2. **检查光模块 CRC 校验错误（PFC Pause Storm）**：
   - 在交换机端执行 `show interfaces counters errors`，若光模块接收端 CRC 错误计数每秒增量 $> 0$，立即隔离对应光纤跳线。
3. **定位网络死锁**：
   - 提取日志中的 `Watchdog thread caught a timeout on rank X`，Rank X 即为首个发生阻塞中断的物理卡。

## 三、 GPU ECC 显存故障分类与自动隔离决策树

NVIDIA HBM 显存发生高能物理粒子轰击或硬件老化时会产生错误校验码（ECC）错误：

```
                              [ GPU 显存监控 Agent ]
                                         │
                                         ▼
                             采集 nvidia-smi 错误计数
                                         │
                    ┌────────────────────┴────────────────────┐
                    ▼                                         ▼
           【单比特纠错 (SBE)】                      【双比特不可逆错误 (DBE)】
      Single-Bit Correctable Error               Double-Bit Uncorrectable Error
                    │                                         │
    - 硬件电路自动透明纠错，无数据丢失         - 显存数据发生物理级破坏，无法自愈
    - 阈值：24小时内累积 < 100 次             - 产生 Xid 48 / Xid 63 / Xid 79 致命中断
    - 动作：记录告警，允许继续训练            - 动作：立即终止 Job 并执行节点隔离
```

### 3.1 双比特致命错误（DBE）自动化处置机制
1. **驱逐（Drain & Cordon）**：
   智算平台调度器监听到节点上报 `DBE Error` 时，在 **5 秒**内将该物理宿主机打上 `gpu-failure=true:NoSchedule` 污点，防止新任务调度进入。
2. **切卡与冷备替换**：
   自动调用备用计算资源池中的健康节点接替该节点，并向机房硬件驻场团队发起换卡工单（RMA）。

## 四、 权重检查点（CheckPoint）存储吞吐性能基线

对于 5000 亿（500B）参数量级的大模型，单次全量权重（包含 FP16 权重、FP32 优化器状态、动量梯度）的体积约为 **3.2 TB**：

### 4.1 写入吞吐与中断停顿限制
- **CheckPoint 保存周期**：固定为每训练 **500 个 Iteration** 执行一次保存。
- **存储吞吐性能要求**：后端分布式对象存储（Ceph / Lustre）必须提供不低于 **80 GB/s** 的聚合写入带宽。
- **训练停顿窗口（Train Bubble）**：单次 CheckPoint 导致模型计算挂起停顿的时间上限为 **90 秒**（采用异步内存快照倾倒技术）。

### 4.2 CheckPoint 校验与断点自愈
- CheckPoint 写入完成后，后台协程异步计算文件的 **SHA-256 校验和**。
- 若发生节点宕机，分布式训练控制器（Elastic Operator）必须在 **8 分钟**内拉起健康节点、加载最近一份合法的 CheckPoint，并恢复张量计算。
