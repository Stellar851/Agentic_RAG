## 一、 流水线安全左移与准入门槛（Quality & Security Gates）

所有推送到生产分支（`main` / `release`）的代码，必须经过自动化 CI/CD 流水线严格把关，实施**“四重安全卡点”**：

### 1.1 静态代码安全扫描（SAST）与单测门禁
- **单元测试覆盖率门禁**：核心交易服务行覆盖率（Line Coverage）不得低于 **80%**，分支覆盖率（Branch Coverage）不得低于 **70%**。
- **高危漏洞扫描拦截**：SonarQube / Fortify 静态扫描中，若发现 **Blocker 或 Critical 级安全漏洞，流水线立即中断并终止构建**，零容忍上线！

### 1.2 软件物料清单（SBOM）与开源组件漏洞（SCA）
- **CVE 严重程度分级卡点**：
  - **CVSS 分数 >= 7.0（High 或 Critical 级别）**：禁止打包生成发布镜像，强制阻断！
  - **CVSS 分数 < 7.0（Medium 级别）**：允许构建，但必须在系统内自动生成 Jira 缺陷工单，整改宽限期为 **14 个自然日**。
- **开源许可证合规排查**：严禁商业专有核心业务静态引入包含强传染性 GPL v3 / AGPL 协议的开源组件（详见《16_企业开源合规审查与知识产权代码许可证治理指南_V3.md》）。

## 二、 生产镜像安全构建与签名规范

1. **基础镜像（Base Image）白名单**：
   - 生产环境统一强制使用由安全部门加固的 Distroless 或 Alpine 极简镜像，严禁开发者私自从公网拉取 `latest` 标签镜像。
2. **Cosign 镜像加密数字签名**：
   - 构建完成的镜像必须使用 KMS 托管的企业根密钥进行数字签名；
   - Kubernetes 准入控制器（Kyverno / OPA Gatekeeper）在 Pod 创建时强制校验签名，**未经验证的非法镜像拒绝拉取并拒绝调度**。

## 三、 金丝雀渐进式灰度发布与回滚 SLA

为降低版本更迭对核心业务的影响，生产环境一律实行金丝雀（Canary）灰度发布策略：

| 灰度阶段 | 流量放行比例 | 阶段观察时间 | 异常指标熔断标准 |
| :--- | :--- | :--- | :--- |
| **第一阶段 (Init Canary)** | **5% 生产流量** | **必须持续观察 30 分钟** | HTTP 5xx 错误率 > 0.2% 或 P99 时延环比增加 > 25% |
| **第二阶段 (Step-1)** | **20% 生产流量** | 观察 60 分钟 | 任何 P1 级业务告警立即终止 |
| **第三阶段 (Step-2)** | **50% 生产流量** | 观察 60 分钟 | 持续无异常方可推进全量 |
| **第四阶段 (Full Release)** | **100% 全量上线** | 连续 24 小时重点盯盘 | 完成正式发版归档 |

### 3.1 自动化一键回滚红线
若灰度期间触发上述任何一项熔断标准，金丝雀控制器必须在 **60 秒内完成全量流量秒级回滚**，恢复至上一稳定版本。
